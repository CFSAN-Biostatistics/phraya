# Phraya Long-Read Benchmark — 2026-10-01

## Summary

**Benchmark executed successfully on Reedling2 HPC.** `phraya align --strategy long-read` was compared against `minimap2 -ax map-ont` on synthetic long reads.

## Actual Results

### Test Data
- Reference: 5 Mb synthetic genome
- Reads: 10 reads, 8-20 kb each (ONT R10.4 error model: 12% total error, 70% indels)
- Generated by: `gen_synthetic_long.py`

### Measured Results

| Aligner | Read Error | Placement Accuracy | Wall (s) | Peak RSS (MB) | Notes |
|---------|-----------|-------------------|----------|---------------|-------|
| phraya-longread | 1% | 10/10 (100%) | 7.64 | ~1470 | WFA succeeds under memory cap |
| phraya-longread | 12% | 0/10 (0%) | 4.79 | ~1470 | All reads: `no_alignment` (WFA fails) |
| minimap2-ont | 12% | 10/10 (100%) | 0.31 | ~117 | Reference baseline |

### Key Finding

`phraya align --strategy long-read` **fails to align** reads at realistic ONT error rates (12%). All 10 reads returned `no_alignment=10` — the WFA extension itself fails, not threshold filtering.

**Root cause confirmed empirically:** At 12% error, the expected edit distance for a 10-20 kb read is ~1,200-2,400, exceeding the 512 MB wavefront memory cap (`default_max_s_cap ≈ 768` for 10 kb reads). With 1% error, WFA succeeds (100% PA).

**The `LongReadAligner` module in `long_read.rs`** provides correct chunked WFA logic but is **not wired** into `extend_chains`/`extend_anchor`.

## Recommendations

### Immediate: Wire Chunked WFA
1. Modify `extend_chains` for `Strategy::LongRead` to use `LongReadAligner.chunk_read()`
2. Split reads into 5 kb chunks (stays under memory cap even at 15% error)
3. Extend each chunk via independent WFA
4. Concatenate CIGARs

### Benchmark Scale-Up
```bash
module load minimap2/2.28 samtools
./scripts/benchmark/slurm/run_benchmark.sh --alphabet long-read
```

## Conclusion

The benchmarking harness is **complete and validated**. The comparison reveals that `phraya align --strategy long-read` is not yet functional for realistic ONT read error rates due to the unbanded WFA memory cap. Implementing the `LongReadAligner` chunking would address this.
